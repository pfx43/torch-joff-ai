4. [技术架构与代码地图](./技术架构与代码地图.md)：开始阅读或修改代码前，理解模块边界和主调用链。

## 本地编译 LaTeX 文档

`docs/` 下的 `.tex` 用 XeLaTeX + ctex 编译（中文）。一键重新生成 PDF：

```bash
pwsh docs\编译PDF.ps1
```

脚本会自动补全 PATH、用 latexmk 跑足够趟数解决目录与交叉引用，把中间文件放到临时目录（保持仓库干净），只把 PDF 取回 `docs/`，并打印质量检查（错误数、中文缺字、未定义引用、超出页宽）。

已装好的依赖（2026-07-26 验证）：MiKTeX 26.5 位于 `%LOCALAPPDATA%\Programs\MiKTeX\miktex\bin\x64`（已在用户 PATH），Perl 位于 `D:\Strawberry\perl\bin`（latexmk 需要）。注意：ctex 需要较新的 expl3/fontspec，若换机器后报 `Support package 'expl3' too old`，先执行 `mpm --update`。

## 文档维护原则

- 日常只需要维护《当前工作记录》，不要每次运行都修改全部文档。
- 普通调试运行由运行目录保存配置、日志和指标，不手工写成文档。
- 只有改变研究判断的实验，才在《当前工作记录》中留下结论。
- 文献矩阵、实验方案和符号表只在进入对应阶段后创建，不提前建立空文件。
- `README.md` 和 `AGENTS.md` 保留工具约定的标准文件名；`docs/` 下的 Markdown 文件使用中文名称。
