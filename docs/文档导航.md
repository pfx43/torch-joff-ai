# 文档导航

本文件是项目文档的唯一入口。第一次进入仓库时，按下面顺序阅读即可。

## 推荐阅读顺序

1. [论文研究完整路线](./论文研究完整路线.md)：先了解论文从零开始应按什么顺序推进。

2. [当前工作记录](./当前工作记录.md)：确认目前做到哪一步、接下来要做什么。

3. [论文写作上下文](../MANUSCRIPT_CONTEXT.md)：进入当前英文稿前，确认理论边界、数据纪律和未决问题。

4. [英文论文稿](../paper/main.tex)：阅读当前方法与论文正文；PDF 是否同步以写作上下文中的状态为准。

5. [技术架构](./技术架构.md)：开始阅读或修改代码前，理解模块边界和主调用链。

6. [目录结构与文件数](./目录结构与文件数.md)：定位目录、核心文件和测试，并核对统计口径。

## 本地编译 LaTeX

当前英文稿：

```bash
latexmk -cd -pdf -interaction=nonstopmode -file-line-error -halt-on-error paper/main.tex
```

只有明确维护归档中文设计稿时才运行：

```bash
pwsh docs\旧文档\编译PDF.ps1
```

本机曾验证 MiKTeX 26.5 与 Strawberry Perl 可用，但当前编译状态必须以 `MANUSCRIPT_CONTEXT.md` 为准。若 ctex 报 `Support package 'expl3' too old`，先执行 `mpm --update`；修改 LaTeX 后不得沿用旧 PDF 宣称编译通过。

## 文档维护原则

- 日常只需要维护《当前工作记录》，不要每次运行都修改全部文档。
- 普通调试运行由运行目录保存配置、日志和指标，不手工写成文档。
- 只有改变研究判断的实验，才在《当前工作记录》中留下结论。
- 文献矩阵、实验方案和符号表只在进入对应阶段后创建，不提前建立空文件。
- `AGENTS.md` 是唯一根级代理入口；不要重新创建平行的工具专用规则文件。
- `README.md` 和 `AGENTS.md` 保留标准文件名；`docs/` 下的 Markdown 文件使用中文名称。
