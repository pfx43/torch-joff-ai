# 目录结构与文件数

## 1. 文档目标

本文集中维护仓库目录职责、文件数量、Joff 核心文件地图和源码阅读顺序。运行时分层、调用链、接口与架构不变量见《[技术架构](./04-技术架构.md)》。

文件统计是时间点快照，不是长期常量。目录或文件发生实质变化时，应重新执行本文第 6 节的命令并更新日期和数字。

### 4.2 源码阅读顺序

1. `experiments/experiment.py`：理解一次实验如何串联所有模块。
2. `core/config.py`、`core/resolver.py`：理解配置来源、校验和覆盖优先级。
3. `data/datamodule.py`：理解原始数据如何变成训练批次。
4. `core/factory.py`、`models/base.py` 和目标模型：理解模型构建与输出约定。
5. `training/trainer.py`：理解训练、评估和 checkpoint。
6. `evaluation/`：理解预测如何转成结构化指标。
7. `experiments/study.py`：理解 sweep、重复实验和结果聚合。

## 6. 重新统计

在仓库根目录执行以下 PowerShell：

```powershell
$files = git ls-files --cached --others --exclude-standard |
    Where-Object { Test-Path -LiteralPath $_ -PathType Leaf }

$files.Count

$files |
    ForEach-Object {
        $top = ($_ -split '[\\/]')[0]
        [PSCustomObject]@{ Top = $top; Path = $_ }
    } |
    Group-Object Top |
    Sort-Object Name |
    Select-Object Name, Count

Get-ChildItem src/joff -Recurse -File |
    Where-Object {
        $_.FullName -notmatch '[\\/]__pycache__[\\/]' -and
        $_.Extension -in '.py', '.typed'
    } |
    Measure-Object

python -m pytest --collect-only -q
```

计数更新后同时检查 `git status --short`，避免把用户正在移动但尚未纳入索引的文件误判为删除。

## 7. 已发现的清单风险

`.gitignore` 中未锚定的 `artifacts/` 规则会命中 `src/joff/artifacts/`。因此该目录的 `__init__.py` 虽然物理存在且被 `joff` 导入，却不在上表 629 个可版本化文件和 `src/` 的 85 个文件中；这正是“物理源码 86”与“可版本化源码 85”的差额。

在干净克隆或发布前，应单独修复忽略规则并确认 `src/joff/artifacts/__init__.py` 被版本控制。本次文档拆分不改动代码或忽略策略，只记录该风险。
