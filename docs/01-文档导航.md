# 文档导航

本文件是项目文档的唯一入口。`docs/` 根目录下持续维护的正式文档统一使用 `01-` 至 `07-` 前缀；第一次进入仓库时，按下面顺序阅读即可。

## 推荐阅读顺序

1. [论文研究完整路线](./02-论文研究完整路线.md)：先了解论文从零开始应按什么顺序推进。

2. [论文实验线详细说明](./07-论文实验线详细说明.md)：单独理解数据怎样分段、实验怎样运行、指标怎样计算，以及每一步怎样验收。

3. [论文代码实施计划](./06-论文代码实施计划.md)：准备开始实现时，查看 P0-P11 的接口、测试、停止条件和 Git 提交计划。

4. [当前工作记录](./03-当前工作记录.md)：确认目前做到哪一步、接下来要做什么。

5. [论文写作上下文](../MANUSCRIPT_CONTEXT.md)：进入当前英文稿前，确认理论边界、数据纪律和未决问题。

6. [英文论文稿](../paper/main.tex)：阅读当前方法与论文正文；PDF 是否同步以写作上下文中的状态为准。

7. [技术架构](./04-技术架构.md)：开始阅读或修改代码前，理解模块边界和主调用链。

8. [目录结构与文件数](./05-目录结构与文件数.md)：定位目录、核心文件和测试，并核对统计口径。

## 本地编译 LaTeX

当前英文稿：

```bash
latexmk -cd -pdf -interaction=nonstopmode -file-line-error -halt-on-error paper/main.tex
```

只有明确维护归档中文设计稿时才运行：

```bash
pwsh docs\旧文档\编译PDF.ps1
```

本机曾验证 MiKTeX 26.5 与 Strawberry Perl 可用，但当前编译状态必须以 `MANUSCRIPT_CONTEXT.md` 为准。若 ctex 报 `Support package 'expl3' too old`，先执行 `mpm --update`；修改 LaTeX 后不得沿用旧 PDF 宣称编译通过。

## 文档维护原则

- 日常只需要维护《当前工作记录》，不要每次运行都修改全部文档。
- 普通调试运行由运行目录保存配置、日志和指标，不手工写成文档。
- 只有改变研究判断的实验，才在《当前工作记录》中留下结论。
- 文献矩阵、实验方案和符号表只在进入对应阶段后创建，不提前建立空文件。
- `AGENTS.md` 是唯一根级代理入口；不要重新创建平行的工具专用规则文件。
- `README.md` 和 `AGENTS.md` 保留标准文件名；`docs/` 下的 Markdown 文件使用中文名称。
