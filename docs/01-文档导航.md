# 文档导航

本文件是项目文档的唯一入口。`docs/` 根目录下持续维护的正式文档统一使用 `01-` 至 `07-` 前缀。老师最新版方法尚未同步到 `paper/main.tex`，因此第一次进入仓库时必须按下面顺序判断来源和状态。

## 推荐阅读顺序

1. [当前工作记录](./03-当前工作记录.md)：先确认老师最新版来源、当前阶段、职责边界、
   阻塞、验证结果和不可声称事项。

2. [论文代码实施计划](./06-论文代码实施计划.md)：查看 V2-P0 至 V2-P8 的模块接口、数据范围、测试、科研图和停止条件。

3. [论文实验线详细说明](./07-论文实验线详细说明.md)：理解五阶段数据怎样流动、基线与消融怎样保持公平、指标和科研图怎样生成。

4. [技术架构](./04-技术架构.md)：开始阅读或修改代码前，理解当前已实现模块和主调用链；计划能力未实现前不会提前写入此文档。

5. [目录结构与文件数](./05-目录结构与文件数.md)：定位目录、核心文件和测试，并核对统计口径。

6. [论文研究完整路线](./02-论文研究完整路线.md)：了解较早形成的研究全局和推进顺序；若与最新版 V2 规格冲突，以前述文档为准。

7. [英文论文稿](../paper/main.tex)：旧 Protected Attention–Koopman 内部稿，尚未与老师最新版同步；仅用于追溯旧理论正文。

老师最新版原始 PDF：
[Measurement-Decoupled Attention–Koopman–T–S Fuzzy Monitoring](<../paper/teacher_latest_manuscript/Measurement_Decoupled_Attention_Koopman_TS_Fuzzy_Monitoring_Skill_Revised(1).pdf>)。
它是当前实验实现的最新需求来源，但老师尚未完成细审，不能据此声称理论已经定稿。

## 本地编译 LaTeX

当前英文稿仍是旧路线。只有理论负责人明确要求同步或编译时才运行：

```bash
latexmk -cd -pdf -interaction=nonstopmode -file-line-error -halt-on-error paper/main.tex
```

只有明确维护归档中文设计稿时才运行：

```bash
pwsh docs\旧文档\编译PDF.ps1
```

本机曾验证 MiKTeX 26.5 与 Strawberry Perl 可用，但当前编译状态和稿件是否代表最新版
必须以《当前工作记录》和本次实际编译结果为准。若 ctex 报
`Support package 'expl3' too old`，先执行 `mpm --update`；修改 LaTeX 后不得沿用旧 PDF
宣称编译通过。

## 文档维护原则

- 日常只需要维护《当前工作记录》，不要每次运行都修改全部文档。
- 普通调试运行由运行目录保存配置、日志和指标，不手工写成文档。
- 只有改变研究判断的实验，才在《当前工作记录》中留下结论。
- 文献矩阵、实验方案和符号表只在进入对应阶段后创建，不提前建立空文件。
- 计划接口只在《论文代码实施计划》中维护；实验矩阵和科研图只在《论文实验线详细说明》中维护。
- 《技术架构》只记录已经实现的运行时，不把 V2 计划能力提前写成当前事实。
- `AGENTS.md` 是唯一根级代理入口；不要重新创建平行的工具专用规则文件。
- `README.md` 和 `AGENTS.md` 保留标准文件名；`docs/` 下的 Markdown 文件使用中文名称。
