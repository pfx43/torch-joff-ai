## 2. 初学者先理解七个词

### 2.1 严格过去

时刻 $k$ 的正常状态编码只能读取 $k$ 之前的历史。当前测量 $y_k$ 可以用于形成残差或训练监督，但不能悄悄进入同一时刻的正常参考。

### 2.2 测量解耦正常参考

它是从延迟确认锚点出发、之后不再用新测量修正的模型参考轨迹。它不是系统真实无故障状态，也不是“知道故障发生后系统本来会怎样”的反事实真值。

### 2.3 start-indexed 残差

`start-indexed` 指自由展开训练、短视野监测和长参考监测都从同一个明确定义的起点计数。若一处把锚点后第一步记为 0，另一处记为 1，窗口、控制输入和标签就会错位。

### 2.4 完整模糊 Jacobian

Jacobian 是模型输出对输入小变化的局部响应矩阵。完整 T–S 模糊 Jacobian既包含局部 Koopman 矩阵的加权和，也包含规则隶属度变化造成的附加项。

### 2.5 模型坐标基扰动

`u/y/z` 分别表示在模型控制输入、模型测量和提升坐标中插入标准基或分组标准基扰动。它们只说明扰动插入位置，不自动说明物理故障来自执行器、传感器还是过程设备。

### 2.6 多尺度分数

同一时刻使用多个预先声明的残差窗口分别评分，再取窗口族最大值。窗口不能在看过故障结果后临时增删。

### 2.7 兼容集合

当观测模式与多个 `u/y/z` 响应组都相容时，结果必须保留全部相容组。只有冻结分离规则支持唯一判断时才能输出单一组。

## 3. 共同不变量

所有 V2 阶段必须维持以下规则：

1. 所有配置严格拒绝未知字段，并保留解析来源和配置 hash。

2. 正常训练、正常估计、检测校准、归因校准和冻结正常测试互斥，段间保留隔离带。

3. 真实冻结故障测试位于五段之外；在模型、窗口、阈值、模式库和代码身份冻结前不得访问。

4. 拟合型预处理只允许在其声明的正常阶段拟合；标准化不得在校准或测试阶段重新拟合。

5. 模型坐标 `u/y/z` 不得在没有额外证据时改名为物理故障类别。

6. 软损失只能称为正则项；只有结构参数化或被验证的确定性上界才能承担硬约束含义。

7. 在线流程不得包含训练、聚类、SVD、特征值分解、大矩阵求逆、高阶导数或长窗口高维优化。

8. synthetic smoke、正常-only development 和未冻结结果必须标记 `formal_fault_results=false`。

9. 任何改变 score map、窗口族、reference state path、标准化或模式库的修改都会使旧校准失效。

## 4. 计划中的深模块与接口

以下模块在文档层面冻结其 seam 和接口语义。内部实现可以拆分，但调用者和公开测试只跨这些接口。

五个深模块共同使用四个轻量值对象，它们不是额外业务模块：

- `ReferenceIdentity`：模型、checkpoint、配置、锚点历史和数据身份的不可变组合；
- `ReferenceSeed`：锚点时刻以及从严格过去历史得到的初始化模型状态；
- `StartIndexedResidualSpec`：首个预测时刻、视野、堆叠顺序以及命令/外生量对齐规则；
- `StartIndexedResidual`：按上述规格形成的观测、预测、残差和逐时刻索引。

V2-P1 必须先冻结这些值对象和纯残差构造函数。V2-P3 只使用同一自由 rollout 内核、
`ReferenceSeed` 和 `StartIndexedResidualSpec` 生成离线扰动响应；V2-P4 再用相同合同实现在线
reference 生命周期。这样 P3 不依赖尚未交付的 P4 状态机，P3 与部署残差又不会形成两套索引。

### 4.1 `MeasurementDecoupledReference`

**职责**：从确认锚点启动并递推测量解耦正常参考，统一保存起点、reference age 和重置原因。

**最小接口**：

- `reset(reference_seed: ReferenceSeed, reference_identity: ReferenceIdentity) -> ReferenceState`
- `step(state, recorded_command, exogenous) -> ReferenceStep`

**输入**：

- 已确认锚点中的模型状态和历史身份；
- 当前记录命令；
- 在线明确可得的外生量；
- 冻结模型和配置身份。

**输出**：

- 当前参考潜变量；
- 参考预测测量；
- reference age；
- 使用的控制与外生量索引；
- 状态转移原因；
- 可重放 trace。

**禁止行为**：

- `step` 接收当前真实测量；
- 用故障报警反向改变锚点确认路径；
- 在未声明情况下使用真实未来输出；
- 把参考称为真实无故障反事实轨迹。

**失败模式**：

- 锚点身份不匹配；
- 输入时间索引不连续；
- 超过冻结最大参考视野；
- 外生条件缺失；
- 模型或 checkpoint 身份变化。

### 4.2 `StructuredBasisResponseGenerator`

**职责**：用普通模型前向 rollout 生成名义残差和 `u/y/z` 三组模型坐标基扰动响应。

**最小接口**：

- `generate(batch, reference_seed, residual_spec, basis_spec) -> StructuredBasisResponse`

**`basis_spec` 必须包含**：

- 组名，只允许 `u`、`y`、`z`；
- 坐标或分组索引；
- 扰动幅值；
- 插入时刻；
- rollout 视野；
- 残差堆叠顺序；
- 数值稳定常数。

**输出对象必须包含**：

- 名义残差；
- 每组每个方向的扰动残差；
- 残差差分；
- 除以扰动幅值后的缩放灵敏度；
- 单位 L1 响应模式；
- 组内和组间距离；
- 模型、配置、batch、参考和 basis 身份。

**禁止行为**：

- 重新训练模型来生成单个响应；
- 直接把 `u/y/z` 写成物理故障标签；
- 使用故障样本选择基方向；
- 在扰动幅值接近零时静默除零。

### 4.3 `OperatingConditionStandardizer`

**职责**：只用正常估计段拟合工况条件均值和尺度，并对后续残差执行冻结变换。

**最小接口**：

- `fit(estimate_episodes, condition_spec) -> FittedStandardizer`
- `transform(fitted, residual, condition) -> StandardizedResidual`

**条件描述至少包含**：

- 模糊运行区域或规则权重摘要；
- 当前记录命令；
- 命令变化；
- 外生运行条件；
- reference age。

**拟合产物必须包含**：

- 条件划分或平滑模型；
- 条件均值；
- 条件方差或稳健尺度；
- 组间均值差带来的混合方差项；
- 样本数和覆盖范围；
- scale floor；
- estimate 数据身份。

**失败模式**：

- 工况不在冻结支持范围；
- 样本数不足；
- 尺度非有限或低于 floor；
- 输入条件缺字段；
- 拟合来源不是正常估计段。

失败时返回明确的 `unsupported`，不得回退到未声明的全局标准化。

### 4.4 `MultiscaleEpisodeCalibrator`

**职责**：把有限窗口族分数、时刻最大值和 episode 最大值组成唯一校准流程。

**最小接口**：

- `score(standardized_residual, window_family) -> MultiscaleScore`
- `fit(calibration_episodes, risk_level, score_map) -> FittedEpisodeThreshold`
- `evaluate(fitted, multiscale_score) -> DetectionDecision`

**冻结对象**：

- 窗口长度集合；
- 每个窗口的有效起点；
- L1 聚合方式；
- 缺失窗口处理；
- 时刻最大值；
- episode maximum；
- reset、mode 和 reference-age 支持；
- 有限样本秩规则。

当请求风险低于 $1/(n_{\mathrm{cal}}+1)$ 能支持的最小分辨率时，阈值必须为正无穷并禁用报警。

### 4.5 `BasisPatternLibrary`

**职责**：冻结 `u/y/z` 响应模式，并对观测标准化残差返回唯一组、兼容集合或 `unsupported`。

**最小接口**：

- `build(basis_responses, pattern_spec) -> UncalibratedPatternLibrary`
- `calibrate(library, attribution_calibration_episodes, fitted_standardizer, calibration_spec) -> FittedPatternLibrary`
- `classify(fitted, standardized_residual, condition) -> BasisGroupDecision`

`AttributionCalibrationEpisode` 是不可变输入对象，必须包含：归因校准阶段身份、episode
身份、由 V2-P4 `fitted_standardizer` 产生的标准化残差序列、逐时刻 condition、standardizer
身份，以及可选的预声明 synthetic `u/y/z` 插入身份。它不接收未经标准化的原始测量或真实
故障标签。`calibrate` 必须核对 episode 与显式传入的 `fitted_standardizer` 身份一致。

若校准唯一性 margin 需要组身份，只能使用在独立正常归因校准 episode 上按预声明方案生成的
synthetic 插入身份。`build` 只形成响应模式，`calibrate` 才冻结兼容容差、唯一性 margin 和
支持范围；两步输入以及 standardizer 身份都必须进入 `PatternLibraryManifest`。

**`BasisGroupDecision` 必须包含**：

- 状态：`unique`、`compatible-set` 或 `unsupported`；
- 兼容组集合；
- 每组距离或相似度；
- 唯一性 margin；
- 工况支持状态；
- 模式库和标准化身份；
- 不包含物理类别保证的固定风险说明。

扩大容差不得让兼容集合反而缩小。模式不可分、工况不覆盖或证据不完整时不得强制 singleton。

## 8. V2-P2：无穷范数界、递推误差界和可靠参考视野

### 当前状态

未实现。现有 Frobenius 约束和 Jacobian product 正则不能直接冒充最新版要求的无穷范数界。

### 目的

把完整模糊 Jacobian 转换成无需在线 SVD、特征值分解或矩阵求逆的可实现传播界，并据此确定参考误差在什么视野内仍低于冻结容差。

### 前置条件

- V2-P1 通过；
- 理论负责人确认需要约束的矩阵、范数、margin 和递推项；
- 所有界中量都能从模型、配置或正常数据获得。

### 允许访问的数据

正常训练和正常估计。不得用故障结果选择 bound margin 或可靠视野。

### 计划接口

- `JacobianInfinityBound`：返回局部动力学项、membership-variation 项和总上界；
- `ReferenceErrorRecursor`：输入初始误差、逐步上界和正常 forcing bound，返回误差上界序列；
- `ReliableReferenceHorizon`：返回满足冻结容差的最大连续视野及首个失效原因。

### 输出产物

- 每步完整 Jacobian 实际无穷范数；
- 可实现上界及分项；
- 递推误差界；
- 可靠视野；
- 训练正则和硬参数化分别采用何种实现的记录。

### 公开测试

- 上界覆盖完整 Jacobian 实际无穷范数；
- 单规则和零 membership-variation 小例子可手算；
- 递推器与人工展开一致；
- 上界增大时可靠视野不得增加；

## 16. 配置与产物身份规则

V2 配置必须分开表达：

- 模型结构；
- Jacobian 上界；
- reference 与锚点；
- basis 组和扰动幅值；
- 结构化损失；
- 条件标准化；
- 窗口族和检测风险；
- 模式库和兼容 margin；
- 数据协议；
- development 或 frozen 模式。

所有会改变预测、残差、标准化、分数、阈值或 group decision 的字段都必须进入配置 hash。理论敏感字段不得使用无法说明来源的隐藏默认值。

每个阶段“输出产物”小节只规定该模块的验收对象，不维护完整运行保存清单。每次运行必须保存
的统一产物及图表来源只以 07 第 13 节为准；06 只要求这些产物的身份字段全部进入配置或
manifest 的可重放链。

## 17. 变更控制

后续老师修改分为三类：

1. **只改理论表述，不改变实现对象**：更新 `MANUSCRIPT_CONTEXT.md`，评估是否影响 06 接口。

2. **改变损失、界、窗口或模式比较策略**：更新对应 V2 阶段，旧训练或校准产物失效。

3. **改变信息路径、数据协议或物理解释**：执行全链 impact review，创建新的协议版本，旧正式结果不得直接复用。

实现者发现公式需要在线不可得量、故障标签或真实无故障反事实时，应停止并形成教师确认问题，不得自行增加假设后继续声称原路线成立。

## 18. 阶段完成的统一定义

一个 V2 软件阶段只有同时满足以下条件才算完成：

- 前置条件和允许数据范围已满足；
- 计划接口已实现且保持小而稳定；
- 公开测试覆盖核心行为和失败模式；
- 相关回归、类型和 lint 检查通过；
- CPU synthetic 或正常-only smoke 可运行；

## 19. 当前实施入口

在开始代码前，先完成 V2-P1 的最新版兼容性审计。不要直接从 V2-P8 真实故障运行倒推需求，也不要先把旧 P6/P7/P9 适配成新名称。

`V2-P1 → V2-P2 与 V2-P3 → V2-P4 → V2-P5 → V2-P6 → V2-P7 → V2-P8`

相同索引合同并接入 V2-P2 的 bound。V2-P6 才同时消费 P3 的 basis 产物和 P4 的标准化身份。
