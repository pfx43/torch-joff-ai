# paper_project 项目特定指引

## 本仓库的文档体系

**重要**：在本仓库使用 `idea-review-and-paper-writing` 技能时，**不要创建** `MANUSCRIPT_CONTEXT.md`。请使用 `docs/` 目录下现有的文档体系。

### 文档映射关系

技能标准的 `MANUSCRIPT_CONTEXT.md` 各章节对应本仓库现有文件如下：

| MANUSCRIPT_CONTEXT.md 章节 | 本仓库对应文件 | 用途 |
|---------------------------|--------------|------|
| 项目身份 | `docs/01-文档导航.md` | 项目概览和导航 |
| 核心问题和贡献范围 | `docs/02-论文研究完整路线.md` | 研究路线和贡献主题 |
| 建模和信息边界 | `docs/04-技术架构.md` | 系统架构和边界 |
| 已选研究路线 | `docs/02-论文研究完整路线.md` | 已确认和探索中的决策 |
| 形式化结果和证明路线 | `docs/02-论文研究完整路线.md` | 理论结果状态 |
| 实验和证据 | `docs/06-论文代码实施计划.md` + `docs/07-论文实验线详细说明.md` | 实施计划和实验设计 |
| 当前任务和进展 | `docs/03-当前工作记录.md` | 活跃工作和未解决问题 |
| 章节规划 | `docs/02-论文研究完整路线.md` | 论文结构 |

### 当技能指令要求操作 MANUSCRIPT_CONTEXT.md 时

当技能要求：
- "读取活跃项目的 `MANUSCRIPT_CONTEXT.md`" → 读取上表列出的 `docs/` 下相关文件
- "创建 `MANUSCRIPT_CONTEXT.md`" → 更新现有的 `docs/` 文件
- "记录到 `MANUSCRIPT_CONTEXT.md`" → 根据内容类型记录到相应的 `docs/` 文件

### 主要工作流程文件

1. **`docs/01-文档导航.md`** - 从这里开始，了解项目概览和文件导航
2. **`docs/02-论文研究完整路线.md`** - 核心研究决策、路线状态、贡献范围
3. **`docs/03-当前工作记录.md`** - 当前任务、最近进展、下一步计划
4. **`docs/04-技术架构.md`** - 技术架构、模型边界、系统设计
5. **`docs/06-论文代码实施计划.md`** - 代码实施路线图
6. **`docs/07-论文实验线详细说明.md`** - 详细实验设计和基线对比

### 符号控制

- 技能的 `NOTATION_LEDGER.md`（符号台账）在需要符号追踪时仍可在项目根目录创建
- 技能的 `SECTION_ROLE_MATRIX.md`（章节职责矩阵）在需要论文结构追踪时仍可在项目根目录创建

### 分阶段执行

- **Stage 1（构思探索）**：将路线决策更新到 `docs/02-论文研究完整路线.md`
- **Stage 2（论文写作）**：从 `docs/` 读取上下文，在项目根目录创建技能要求的标准控制产物（`NOTATION_LEDGER.md`、`SECTION_ROLE_MATRIX.md`）

### 理由说明

本仓库使用了成熟的 `docs/` 体系，采用编号文件以便清晰导航。现有文件已包含所有原本应记录到 `MANUSCRIPT_CONTEXT.md` 的信息，且组织方式适合本项目的工作流程。创建平行的 `MANUSCRIPT_CONTEXT.md` 会导致重复和同步问题。
