# Skill Update Log - 2026-07-30

## 更新背景

根据论文写作评审会议纪要，整合了 AI 生成论文的核心质量问题和修改要求到现有 Skill 体系。

## 核心问题识别

### 语言表述类问题
1. **表述生硬**：陈述句堆砌，无句式变化，读起来像命令
2. **逻辑缺失**：只罗列结果不说明原因，无因果链
3. **内容分散**：同时覆盖多个方向，未聚焦单一突破点

### 内容架构类问题
1. **符号使用混乱**：字母复用，变量无前置说明
2. **章节内容错位**：创新方法内容出现在基础理论部分
3. **叙事逻辑倒置**：先堆砌细节，后说明整体目标

## 具体修改内容

### 1. `typical-errors.md` - 新增两个错误类别

#### 新增：Language expression and sentence variety（语言表述与句式多样性）
- 陈述句堆砌问题 → 要求使用多样句式（主被动、从句、非谓语、状语等）
- 只写结果不写原因 → 要求先因后果（reason → method → outcome）
- 先写细节后写整体 → 要求自顶向下（总体架构 → 模块 → 参数）
- 变量突然出现 → 要求先定义后使用，说明作用和关联
- 段落无主题 → 要求每段有明确目的（介绍模块/支持论点/逻辑过渡）
- 缺乏逻辑连接词 → 要求使用明确的因果/对比/时序连接

#### 新增：Narrative structure and exposition order（叙事结构与呈现顺序）
- 创新内容错放在第二章 → 明确第二章只放标准背景，创新放第三章
- 先讲细节后讲整体 → 要求「系统定义→结构堆叠→组件设计→细节解释」
- 先讲参数后讲目标 → 要求先说明设计目标和问题，再引入构造
- 相关内容分散 → 要求将紧密耦合的内容组织到一个逻辑链中

### 2. `living-user-rules.md` - 增强核心写作原则

**修改位置**：Current rules 部分的前几条规则

**新增内容**：
- 句式多样性要求：避免陈述句堆砌，使用主被动、从句、非谓语、介词短语、状语、形容词副词
- 因果逻辑要求：
  - 段内：先因后果（为什么需要 → 做了什么）
  - 段间：从宏观到微观（总体架构 → 模块 → 参数）
  - 遵循「系统定义→结构堆叠→组件设计→细节解释」
- 主题性要求：每段必须有明确作用（介绍构造/支持贡献/建立过渡/推进论证），删除凑字数内容
- 第二章边界：明确第二章只含标准背景定义，不含论文专有构造、新颖组合、attention 机制或方法创新

### 3. `manuscript-quality-gates.md` - 强化七项强制审查

#### 修改审查项 1：Chapter and subsection arrangement
**新增检查点**：
- 验证第二章只含标准背景和问题陈述，所有创新必须在第三章
- 确认呈现遵循自顶向下：总体架构 → 模块 → 参数
- 变量不得在定义上下文之前出现

#### 修改审查项 2：Sentence-to-sentence logic → Sentence-to-sentence logic and language variety
**新增检查点**：
- 避免陈述句堆砌，使用多样句式（主被动、从句、非谓语、介词短语、状语、形容词副词）
- 验证每段有明确目的：介绍模块/支持论点/逻辑过渡
- 删除凑字数段落

#### 修改审查项 3：Narrative causality → Narrative causality and exposition order
**新增检查点**：
- 段内：先因后果（动机/问题/局限 → 构造/结果）
- 段间/小节间：从宏观到微观（总体映射和目标 → 模块结构 → 参数细节）
- 验证变量在使用前已定义（H、S、ρ、ω 等不能在说明其所属系统之前出现）

## 规则整合原则
